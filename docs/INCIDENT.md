# Если случилась утечка или взлом

1. Закрыть доступ: отключить затронутые учётные записи (`set_member_status`), сменить ключи в Supabase, токен бота.
2. Сохранить следы: выгрузить `audit_log` и логи сервера за период.
3. В течение 24 часов — первичное уведомление Роскомнадзора об утечке персональных данных,
   в течение 72 часов — результаты расследования (152-ФЗ, ст. 21). Текст согласовать с юристом.
4. Найти причину, исправить, добавить тест, который ловит эту ошибку.
5. Записать разбор в этот файл: дата, что случилось, что исправлено.

# Если владелец потерял телефон с кодами (второй фактор)

Права владельца без кода не работают, а войти без кода нельзя — поэтому сброс делается на сервере.
1. Убедиться, что просит именно владелец (лично или по телефону), а не тот, кто завладел его Telegram.
2. Supabase → SQL Editor:
   `delete from auth.mfa_factors where user_id = (select id from public.profiles where telegram_id = <ID Telegram владельца>);`
3. Владелец открывает приложение из бота и подключает аутентификатор заново.
4. Записать в журнал разбора: дата, кто просил, кто сбросил.

Чтобы до этого не доходило: при подключении добавить ключ в два места (например, «Пароли» на iPhone
и Яндекс Ключ на втором телефоне).
