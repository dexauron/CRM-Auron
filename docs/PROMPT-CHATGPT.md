# Сообщения для передачи работы между ИИ

Владелец копирует нужный блок целиком и отправляет исполнителю. Подробный протокол — `docs/HANDOFF.md`, раздел 0.

## 1. Для ChatGPT (или Codex) — принять работу у Claude

```
Ты продолжаешь проект CRM «Way Market» после Claude.
Репозиторий: https://github.com/dexauron/CRM-Auron (публичный).

1. Прочитай docs/HANDOFF.md целиком: сначала раздел 0 (протокол передачи) и раздел 11 (последняя запись
   журнала — свежее состояние), затем AGENTS.md и файлы из раздела 2.
2. Проверь состояние сам: последние коммиты main, открытые PR, CI. Если что-то не сходится с журналом —
   скажи мне и запиши в свою запись журнала.
3. Продолжай с раздела 8 «Что делать дальше». Дизайн — строго docs/DESIGN.md (стиль iOS), безопасность —
   раздел 7. Каждый шаг: тесты, PR, зелёный CI, запись в docs/PROGRESS.md.
4. Никогда не проси у меня токены, пароли, ключи и не пиши их в репозиторий. Если не хватает доступа
   (GitHub, Supabase) — скажи, какого именно, и дай мне инструкцию по пунктам с названиями кнопок.
5. Объясняй мне просто, по-русски: я не программист.
6. Когда закончишь или почувствуешь, что заканчиваются лимиты, — до последнего сообщения выполни
   раздел 0 «Когда заканчиваешь»: незаконченное — в PR-черновик, запись в журнал (раздел 11) по шаблону,
   обнови разделы 4 и 8 и docs/PROGRESS.md. Потом дай мне заполненное сообщение для Claude по шаблону
   из docs/PROMPT-CHATGPT.md, раздел 2.

Продолжай.
```

## 1а. Для ChatGPT — работать параллельно с Claude (с 2026-10-02)

```
Ты работаешь над CRM «Way Market» параллельно с Claude, в одном репозитории:
https://github.com/dexauron/CRM-Auron (публичный). Сначала прочитай AGENTS.md и docs/HANDOFF.md,
раздел 0 «Параллельная работа» — там твоя зона файлов. Claude сейчас переделывает интерфейс
(web/src/**) — туда не заходи, иначе будут конфликты.

Твои задачи по порядку:

1. Проверка безопасности базы. Прочитай все supabase/migrations/*.sql и найди слабые места: правила RLS,
   функции SECURITY DEFINER (проверка роли и магазина, search_path), права grant/revoke на столбцы,
   утечки между магазинами, обход второго фактора (aal2), подделка автора записи, переполнения и
   отрицательные числа, удаление вместо мягкого удаления. На каждую находку — тест, который её
   доказывает или опровергает: supabase/tests/security_review_test.sql (по образцу других *_test.sql,
   данные только вымышленные, всё откатывается). Итог — docs/SECURITY-REVIEW.md: что проверено,
   что найдено, насколько опасно. Исправление — только НОВЫМ файлом миграции в отдельном PR;
   старые миграции не менять, DROP и удаление данных не применять.
2. Скорость первой загрузки каталога для покупателя. Сейчас 19 тыс. товаров качаются страницами
   по 1000 (web/src/api/catalog.ts, loadCatalog), и несколько секунд экран пустой. Сделай быстрее
   (параллельные запросы, компактный формат через новую функцию-RPC, сжатие, частичная отдача —
   выбери и обоснуй в docs/CODEX-NOTES.md с замерами «до» и «после»). Условие: то, что экспортирует
   loadCatalog, не меняется, кроме нового необязательного параметра onProgress(loaded, total) —
   Claude подключит его в интерфейсе. Права гостя не расширять: гость получает только открытую
   часть каталога, как сейчас.

Правила:
- Ветки codex/…, PR — черновиком; CI должен быть зелёным (lint, typecheck, тесты, сборка, база).
- Свой PR в своей зоне сливай сам после зелёного CI. PR с новой миграцией не сливай — его проверит,
  сольёт и применит к облаку Claude (у него доступ к Supabase).
- Свои записи веди в docs/CODEX-NOTES.md (новые сверху): что сделано, чем проверено, что дальше.
  docs/HANDOFF.md и docs/PROGRESS.md не правь — их ведёт Claude.
- Никаких паролей, ключей, токенов и настоящих данных в репозитории. У меня ничего такого не спрашивай.
- Нужна правка в чужой зоне — напиши мне коротко, что передать Claude.
- Объясняй мне просто, по-русски: я не программист.
```

## 2. Для Claude — принять работу обратно (заполняет уходящий исполнитель)

```
Claude, продолжай проект dexauron/CRM-Auron. После тебя работал <ChatGPT / Codex>.
Прочитай docs/HANDOFF.md: раздел 11, запись от <дата> «<кто> → Claude».

Коротко:
- Сделано: <PR и что в них>
- Не сделано или начато: <ветки/PR, что осталось>
- Сломано или под вопросом: <что>
- Нужно от владельца: <что уже сделано владельцем, что нет>
- Следующий шаг: <1–3 пункта>

Проверь мои изменения (CI, тесты, миграции в облаке) и продолжай.
```
