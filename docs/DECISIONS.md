# Решения

Формат: дата — решение — причина (— что отвергнуто).

## 2026-10-02 — Тестовая база в Supabase Cloud
Разработка и тесты идут в Supabase Cloud (`CRM-Auron-Test`, eu-central-1): бесплатно и быстро, сервер в РФ ещё не выбран.
Ограничение: только вымышленные данные. Настоящие данные покупателей и сотрудников — только на сервере в РФ (152-ФЗ).

## 2026-10-02 — Таблица профилей называется `profiles`
Имя `users` занято схемой `auth` Supabase; путаница опасна.

## 2026-10-02 — Права проверяются по базе при каждом запросе
Роль хранится в `memberships`, правила RLS вызывают `private.has_role()`. Отключённый сотрудник теряет доступ сразу,
без ожидания истечения токена. — Отвергнуто: роли в JWT (доступ живёт до истечения токена).

## 2026-10-02 — Служебная схема `private`
Функции для правил доступа и триггеров лежат в схеме `private`, не открытой через API: их нельзя вызвать из браузера.

## 2026-10-02 — Приглашения
Токен 256 бит показывается один раз, в базе только SHA-256; срок 1–168 часов; одноразовый.
Роль владельца приглашением не выдаётся; покупатели регистрируются сами.

## 2026-10-02 — Телефон и telegram_id пишет только сервер
Браузеру нельзя доверять подтверждение номера; номер приходит из Telegram через бота.

## 2026-10-02 — TypeScript 6, а не 7
typescript-eslint 8.71 поддерживает TypeScript до 6.0. Переход на 7 — когда линтер его поддержит.

## 2026-10-02 — Политика CSP вставляется только в сборку
GitHub Pages не даёт задавать заголовки, поэтому CSP — meta-тегом; в режиме разработки Vite использует встроенные стили,
которые строгая политика блокирует. Адрес сервера в `connect-src` берётся из `VITE_SUPABASE_URL`.

## 2026-10-02 — Сервис-воркер не кэширует ответы сервера
В ответах могут быть персональные данные; офлайн-кэш каталога будет отдельным (IndexedDB, этап 1).

## 2026-10-02 — Зависимости
react, react-dom — интерфейс; @supabase/supabase-js — связь с сервером; workbox-window — обновление PWA (нужен
vite-plugin-pwa). Разработка: vite, @vitejs/plugin-react, vite-plugin-pwa, typescript, vitest, eslint и плагины.
Версии закреплены точно (`--save-exact`), обновления — через Dependabot.

## 2026-10-02 — gitleaks через Docker-образ по дайджесту
Не нужен лицензионный ключ и стороннее действие; образ закреплён по sha256, как действия — по хэшу коммита.

## 2026-10-02 — SDK Telegram подключается только при запуске из Telegram
Раньше скрипт `telegram-web-app.js` стоял в `index.html` с `defer`: если telegram.org отвечал медленно или запрос
зависал, событие загрузки не наступало и приложение не запускалось (пустой экран). Теперь SDK подгружается
асинхронно, только когда в адресе есть параметры Telegram (`tgWebApp…`) или они сохранены при перезагрузке,
и не дольше 4 секунд. Обычный браузер к telegram.org не обращается вовсе — меньше стороннего кода и утечек о посещении.

## 2026-10-02 — Вход через Telegram без паролей
Функция `auth-telegram` проверяет подпись `initData` по алгоритму Telegram (HMAC-SHA256, ключ выводится из токена
бота), срок — 1 час. Затем: учётка `tg<id>@telegram.invalid` через admin API → одноразовая ссылка `generateLink` →
`verifyOtp` → обычная сессия Supabase. Пароля нет вовсе; адрес фиктивный (домен `.invalid` почту не принимает).
Связь с Telegram — в `app_metadata` (меняет только сервер) и `profiles.telegram_id`.
Свои JWT не выпускаем: для этого пришлось бы держать в функции секрет подписи проекта.

## 2026-10-02 — Открытая регистрация по почте выключена
Иначе адрес `tg<id>@telegram.invalid` можно занять заранее. Даже если регистрацию включат, функция не войдёт
в такую учётку: своей она считает только учётку с тем же `telegram_id` в `app_metadata` и иначе отвечает 409.
Этой же проверкой чинится недописанный профиль: учётка создана, а запись `profiles.telegram_id` сорвалась.

## 2026-10-02 — Сессия в браузере
supabase-js хранит сессию в localStorage. В Telegram при каждом запуске `telegram_id` сессии сверяется
с пользователем Telegram; если это другой человек на том же устройстве — вход заново.
От кражи сессии через внедрение скриптов защищают CSP и запрет вставки HTML.

## 2026-10-02 — Приглашение через start_param
Ссылка `https://t.me/<бот>?startapp=inv_<токен>` открывает приложение, после входа вызывается `accept_invite`.
Повтор при перезагрузке страницы отсекается отметкой в sessionStorage (первые 8 символов токена — по ним
приглашение не принять).

## 2026-10-02 — Ограничение частоты проверок входа (вероятно, понадобится поднять)
Все входы идут через одну функцию, а Supabase ограничивает проверки одноразовых ссылок: 30 за 5 минут
с одного адреса (`token_verifications`). Для одного магазина этого, вероятно, хватит: сессия живёт долго
и обновляется из браузера. Если покупатели начнут получать «Вход временно недоступен» —
поднять лимит в Supabase → Authentication → Rate Limits.

## 2026-10-02 — Отключение участника закрывает все его сессии
`set_member_status(..., 'disabled')` удаляет записи `auth.sessions` этого человека (токены обновления удаляются
каскадом). Уже выданный токен доступа живёт до часа, но права проверяются по базе при каждом запросе,
поэтому доступа к магазину у него нет сразу. Он выходит и из других магазинов, если состоит в нескольких:
для одного магазина это допустимо, войти снова через Telegram он может, но без прав.

## 2026-10-02 — Срок приглашения включительно
Приглашение недействительно, если `expires_at <= now()`. Раньше было `<`, и приглашение, отозванное
в ту же секунду, ещё принималось. Нашёл тест `team_test.sql`.

## 2026-10-02 — Имя бота в настройках сборки
`VITE_TELEGRAM_BOT` (по умолчанию `auron_core_bot`). Имя бота — не секрет: из него собираются ссылки-приглашения.

## 2026-10-02 — Дизайн в стиле iOS
Сгруппированные списки как в «Настройках» iPhone, системный шрифт, цвета из Apple Human Interface Guidelines,
настоящая тёмная тема, большой заголовок со сворачиванием в полупрозрачную панель.
Минимализм: состояние связи показывается только при проблеме; значки платформы и «Сервер на связи» убраны.
Детали интерфейса собраны в `web/src/shared/ui/` (секция, строка, аватар, сегменты, значки) — новые экраны
собираются из них. Внутри Telegram страница берёт цвета секций и разделителей из темы Telegram, а шапка
Telegram окрашивается в цвет страницы (`setHeaderColor`). Красный и зелёный — варианты с повышенной
контрастностью (WCAG AA для обычного текста).

## 2026-10-02 — Второй фактор: код из приложения-аутентификатора (TOTP)
Права владельца, управляющего и бухгалтера база даёт только в сессии уровня aal2 (`private.has_role`,
`private.can_view_profile`). Без кода человек остаётся участником, видит свой магазин и роль — и экран
«Защита входа». Почему TOTP, а не SMS: бесплатно, работает без связи, не перехватывается подменой SIM;
входит в Supabase без доплат. Почему проверка в базе, а не в интерфейсе: интерфейс можно обойти, правила
доступа — нет. Сброс при потере телефона — вручную на сервере (`docs/INCIDENT.md`).

## 2026-10-02 — Вход с ПК: своё окно Telegram вместо готовой кнопки
Готовая кнопка Telegram Login (`telegram-widget.js` с `data-onauth`) исполняет код через `eval`, что запрещено
нашей CSP. Поэтому сайт сам открывает окно `oauth.telegram.org/auth` (как это делает `Telegram.Login.auth`
в том же скрипте) и принимает ответ сообщением от окна или запросом `/auth/get`; сторонний скрипт не грузится.
Подпись данных проверяет функция `auth-telegram` (алгоритм виджета: `secret = SHA256(токен)`), срок — час.
Номер бота окно берёт у функции (`GET`), он не секретен; при смене токена номер бота не меняется.

## 2026-10-02 — Каталог: открытая и закрытая части в разных таблицах
Правила доступа (RLS) скрывают строки, а не столбцы. Поэтому `products` хранит только то, что можно показать
гостю (название, коды, цена на полке, «есть / нет», дата поступления), а закупка, остаток числом и примечание —
в `product_internals` (читают владелец, управляющий, бухгалтер со вторым фактором; меняет владелец).
«Есть / нет» в `products` обновляет триггер из остатка. Гость находит магазин по `slug`, если у магазина
`catalog_public = true`. Деньги — копейки (`bigint`). История цен пишется триггерами.

## 2026-10-02 — Открытый код со стороны
Владелец разрешил брать готовые решения с GitHub. Правила: лицензия MIT / Apache / BSD / ISC (не GPL / AGPL);
проект живой; небольшой; ставится через npm с точной версией (не с чужого сервера); проходит `npm audit` и CodeQL.
Кандидаты: ZXing (сканер штрихкода на iPhone), библиотека чтения Excel для выгрузок 1С, `idb` (каталог офлайн).
Поиск — перенос своего алгоритма из старого каталога вместе с его эталонными тестами (готовые Fuse.js и MiniSearch
не проходят наши случаи вроде «вода» ≠ «Водолей» и «рис» ≠ «Ирис» без доработки).

## 2026-10-02 — Фото товаров: открытая корзина, запись по папке магазина, EXIF убирает телефон
Каталог открыт гостям, на фото — только товар, поэтому корзина `product-photos` публичная: фото грузятся прямой
ссылкой и кэшируются браузером, без подписанных ссылок. Писать и удалять можно только в папку своего магазина
(`<магазин>/<товар>/<имя>.jpg`), роль владелец или управляющий со вторым фактором — проверяет политика Storage.
Фото перерисовывается на телефоне (холст → JPEG 1280 px, копия 240 px): это и удаляет EXIF (геолокацию, модель
телефона), и экономит место и трафик. Готовые библиотеки сжатия не нужны — хватает встроенного в браузер холста.
Преобразование картинок Supabase (imgproxy) платное, поэтому миниатюра делается при загрузке.

## 2026-10-02 — Каталог на устройстве: версия вместо скачивания при каждом входе
Каталог целиком (~1 МБ сжатым на 19 тыс. товаров) при каждом входе быстро съел бы бесплатный лимит трафика
Supabase и медленно открывался бы на мобильном интернете. Поэтому устройство хранит последнюю копию в IndexedDB
(своя обёртка на 50 строк, без библиотеки) и спрашивает у сервера только версию: `catalog_version` — хэш id и
времени правки товаров и групп и всех штрихкодов. Хэш, а не «последнее время правки»: долгая транзакция,
начатая раньше, могла бы закоммититься позже и не сдвинуть максимум. Функция `security definer`, но проверяет
доступ один раз той же `private.catalog_visible`, что и RLS (построчная проверка стоила ~0,5 с), и наружу отдаёт
только хэш. На устройстве — только открытая часть каталога; закупка и остатки не сохраняются.

## 2026-10-02 — Сканер: встроенный распознаватель, иначе zxing-wasm со своего сайта
Где браузер умеет сам (`BarcodeDetector`: Android, Chrome) — используем его: быстро и без загрузки. На iPhone
и ПК его нет, поэтому запасной — `zxing-wasm` (MIT, живой проект, порт zxing-cpp; точнее чистого JS-порта
`@zxing/library`, который в режиме поддержки). Файл `.wasm` (~1 МБ, 416 КБ сжатым) лежит на нашем сайте и
грузится только при первом сканировании без встроенного распознавателя, затем кэшируется. Для WebAssembly
в CSP добавлен `'wasm-unsafe-eval'`: он разрешает только компиляцию wasm, `eval` для JavaScript по-прежнему
запрещён. Telegram `showScanQrPopup` не подходит — он читает только QR, а не EAN.

## 2026-10-02 — Импорт каталога: одна серверная функция, повтор без дублей
Импорт идёт через RPC `import_catalog` (владелец или управляющий, второй фактор), а не прямой записью в таблицы:
так проверка прав, защита от чужого магазина и правила слияния — в одном месте и покрыты тестом. Товар
сопоставляется по коду кассы (его знает 1С), без кода — по id старого каталога; пустое значение в файле
не затирает имеющееся; штрихкоды только добавляются (удаление — отдельным действием). Части до 2000 строк:
перенос 18 945 товаров идёт ~8 с с ходом выполнения. Старый каталог берётся из его открытых данных на GitHub
(`raw.githubusercontent.com` разрешён в CSP только для этого; закупок и остатков там нет). После переноса
источник и разрешение в CSP можно убрать.

## 2026-10-02 — Поиск каталога: перенос старого алгоритма, ищет устройство
Каталог (до 50 тыс. товаров) загружается целиком и ищется на устройстве: мгновенно, работает без сети (КАТ-8),
не нагружает сервер. Алгоритм — перенос из старого каталога (`search.ts`) с его 15 эталонными случаями.
Ускорения без смены выдачи: пары букв названий считаются один раз; сравнение — слиянием отсортированных
списков; разбору опечаток отдаются не больше ~1500 самых похожих товаров (равных не делим).
Замер на старом каталоге (18 945 товаров): повторный поиск 30–180 мс, число найденного как в старом каталоге.
Экран и группа — в адресе (`#catalog`, `#catalog/<группа>`): системная «Назад» работает как в приложении.
